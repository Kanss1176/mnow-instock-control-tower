# MNow Instock Control Tower (method demonstration)

An independent analytics project modelled on the responsibilities of a quick-commerce **instock analyst**:
inventory health, stockout/overstock risk, persistence of availability gaps, replenishment-model adherence,
redistribution, and event readiness. **Not affiliated with Myntra. Contains no Myntra data.**

## Data classes (read first)

| Class | Tables / files | Meaning |
|---|---|---|
| OBSERVED | `hex_potential.parquet` (OpenStreetMap), `weather_daily.parquet` (Open-Meteo) | Real public data, once you run the ingest scripts |
| ASSUMED | `config.py` values marked ASSUMED, `data/raw/events*.csv` uplifts | My assumptions, listed and stress-tested |
| SIMULATED | `sim_*` tables, `dim_sku` | Generated by `simulator.py`. **Not real inventory.** |

Until you run the Atlas ingest, store potential is a **random placeholder** (control C9 warns). Event dates are
**unverified** until you fill `source_url` (control C8 warns).

## Run
```
pip install -r requirements.txt
python -m pytest -q                         # 16 tests
python -m mnow_instock.atlas.ingest_osm     # needs internet; writes data/processed/hex_potential.parquet
python -m mnow_instock.atlas.ingest_weather # needs internet
cp data/raw/events_template.csv data/raw/events.csv   # verify dates, add source_url
python -m mnow_instock.build_db             # simulate, run controls, build views
```

## What exists now (Phase 1)
- Simulator with censored sales, lead-time variability, case packs, supply shortfalls, injected deviations
  with **ground-truth cause labels** kept in a separate `sim_truth_daily` table.
- 9 data controls (7 errors, 2 warnings) that log exceptions and never silently correct them.
- SQL views: daily inventory health, weekly KPIs, persistence (A5), and evaluation-only views.
- Atlas ingest (OSM to H3 hexes, weighted score, Dirichlet weight-sensitivity) and weather ingest.

## Limits you must state
1. **Circularity.** The simulator and the replenishment policy are both mine. The generator contains shocks and a
   regime break the policy never sees, but results still describe behaviour under my assumptions only.
2. **Truth tables.** `sim_truth_daily` (true demand, lost sales, true cause) cannot exist in real data.
   Only `eval_*` views may use it.
3. **Placeholder baseline.** The first policy I wrote trapped slow SKUs in permanent stockout (instock 28-50%).
   I added a minimum display quantity (`min_display_packs`); this is an assumption, not an observation.
4. **Search/geography is not sales.** The potential index describes location features, not Myntra demand.
